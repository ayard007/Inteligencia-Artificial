i Introducción al proyecto

Lee, entiende y conecta con el código

En este proyecto vas a construir y personalizar la Inteligencia Artificial de un videojuego: un laberinto donde controlas a un personaje que recoge monedas mientras dos fantasmas lo persiguen. Cada fantasma usa un algoritmo de búsqueda distinto. Tu trabajo durante dos semanas es entender cómo funciona y luego hacerlo mejor.

Esta guía está pensada para que leas cada explicación y la conectes con el código que la acompaña. Al final de cada sección encontrarás un recuadro "Conecta con el código" que te dice qué parte del juego corresponde a lo que acabas de aprender, y un reto para modificarlo.

Lo que lograrás. Un juego interactivo y funcional, que integra los cuatro temas del Bloque III, con tu propia versión personalizada de la IA.

1 El laberinto como grafo (Semana 8)

Espacio de estados

El primer paso para que un fantasma "piense" es representar el laberinto como un grafo: cada casilla libre es un estado (nodo) y cada movimiento posible entre casillas vecinas es una acción (arista). El conjunto de todas las casillas es el espacio de estados.

En el código del juego, el laberinto se escribe como texto (# es muro, espacio es pasillo) y una función lo convierte en grafo:

// Cada casilla libre apunta a sus vecinas (sin muros)
function construirGrafo(mapa){
  var g = {};
  for(var r=0; r<mapa.length; r++){
    for(var c=0; c<mapa[0].length; c++){
      if(mapa[r][c] !== "#"){        // es un estado valido
        var vecinos = [];
        var dirs = [[-1,0],[1,0],[0,-1],[0,1]]; // operadores
        for(var d=0; d<4; d++){
          var nr=r+dirs[d][0], nc=c+dirs[d][1];
          if(mapa[nr] && mapa[nr][nc] && mapa[nr][nc] !== "#")
            vecinos.push(nr+","+nc);
        }
        g[r+","+c] = vecinos;
      }
    }
  }
  return g;
}

Conecta con el código

La lista dirs son los cuatro operadores (arriba, abajo, izquierda, derecha). La condición !== "#" es la regla que impide atravesar muros. El resultado g es el espacio de estados completo del juego.

2 Formular el problema del fantasma (Semana 8)

Estado inicial, meta, operadores

La tarea de cada fantasma es un problema de búsqueda: encontrar el camino de su posición hasta el jugador.

  • Estado inicial: la casilla donde está el fantasma.
  • Meta: la casilla donde está el jugador.
  • Operadores: moverse a una casilla vecina (las aristas del grafo).
  • Prueba de meta: el fantasma ocupa la misma casilla que el jugador.
Idea clave. La meta del fantasma cambia en cada turno, porque el jugador se mueve. Por eso el fantasma debe recalcular su camino constantemente: eso es lo que lo hace parecer "inteligente".

Conecta con el código

En el juego, el estado inicial y la meta no son fijos: son las variables fantasma y jugador, que se actualizan cada turno. La búsqueda se vuelve a ejecutar en cada movimiento.

3 Búsquedas no informadas: BFS y DFS (Semana 9)

Explorar sin pistas

La búsqueda en amplitud (BFS) explora el laberinto por niveles, usando una cola, y siempre encuentra el camino más corto. La búsqueda en profundidad (DFS) usa una pila y se adentra por un camino hasta el fondo. Así se ve BFS en el juego:

// BFS: encuentra el camino mas corto del fantasma al jugador
function bfs(grafo, inicio, meta){
  var frontera = [[inicio]];      // cola de caminos
  var visitados = {};
  while(frontera.length > 0){
    var camino = frontera.shift();  // saca el PRIMERO (FIFO)
    var nodo = camino[camino.length-1];
    if(nodo === meta) return camino;  // prueba de meta
    if(!visitados[nodo]){
      visitados[nodo] = true;
      var vecinos = grafo[nodo];
      for(var i=0; i<vecinos.length; i++)
        frontera.push(camino.concat([vecinos[i]]));
    }
  }
  return null;
}
BFS vs DFS. Cambiar frontera.shift() (saca el primero, cola) por frontera.pop() (saca el último, pila) convierte este BFS en DFS. Pruébalo y observa cómo cambia el camino.

Conecta con el código

Esta función es la que da "vista" al Fantasma 2. Devuelve la lista completa de casillas del fantasma al jugador; el fantasma solo avanza a la siguiente, camino[1], en cada turno.

4 Búsqueda informada: A* y la heurística (Semana 10)

Buscar con una pista

A* es más listo que BFS: usa una heurística h(n), una estimación de cuánto falta para la meta (aquí, la distancia Manhattan). Combina lo recorrido g(n) con lo estimado h(n) para dirigirse hacia el jugador explorando menos casillas.

// A*: f(n) = g(n) + h(n)
function manhattan(a, b){
  var pa=a.split(","), pb=b.split(",");
  return Math.abs(pa[0]-pb[0]) + Math.abs(pa[1]-pb[1]); // heuristica
}
function aEstrella(grafo, inicio, meta){
  var abierta = [{f:0, nodo:inicio, camino:[inicio]}];
  var visitados = {};
  while(abierta.length > 0){
    abierta.sort(function(x,y){ return x.f - y.f; }); // menor f primero
    var actual = abierta.shift();
    if(actual.nodo === meta) return actual.camino;
    if(!visitados[actual.nodo]){
      visitados[actual.nodo] = true;
      var vecinos = grafo[actual.nodo];
      for(var i=0; i<vecinos.length; i++){
        var g = actual.camino.length;        // costo recorrido
        var h = manhattan(vecinos[i], meta);   // estimacion
        abierta.push({f:g+h, nodo:vecinos[i], camino:actual.camino.concat([vecinos[i]])});
      }
    }
  }
  return null;
}

Conecta con el código

La función manhattan es la heurística: la pista que guía al Fantasma 1. Si la cambias para que devuelva 0, A* pierde su pista y se comporta como BFS. Lo probarás en el laboratorio de la Semana 2.

6 La IA de los fantasmas: determinístico o no (Semana 8)

El azar que hace justo al juego

Si un fantasma siempre usa su algoritmo, es determinístico: imposible de esquivar. Para que el juego sea justo, cada fantasma tiene una probabilidad de distraerse y moverse al azar, volviéndolo no determinístico. Así se decide cada paso:

// Decide el siguiente paso de un fantasma
function pasoFantasma(fantasma, metodo, distraccion){
  if(Math.random() < distraccion){        // se distrae (no determinista)
    var vecinos = grafo[fantasma];
    return vecinos[Math.floor(Math.random()*vecinos.length)];
  }
  // persigue con su algoritmo (determinista)
  var camino = (metodo === "astar")
      ? aEstrella(grafo, fantasma, jugador)
      : bfs(grafo, fantasma, jugador);
  if(camino && camino.length > 1) return camino[1]; // avanza un paso
  return fantasma;
}

Conecta con el código

La variable distraccion controla el determinismo: 0 = fantasma perfecto (determinista), 1 = totalmente al azar. En el laboratorio podrás moverla con un control deslizante y sentir cómo cambia la dificultad.

7 CSP: colocar las monedas con restricciones (Semana 11)

Satisfacción de restricciones

Las monedas no se colocan en cualquier lugar: deben cumplir restricciones simultáneas (un CSP): no sobre un muro, no encima del jugador o un fantasma, y separadas entre sí. El código elige casillas que cumplan todas las reglas:

// CSP: coloca monedas que cumplan todas las restricciones
function colocarMonedas(cantidad, separacion){
  var libres = Object.keys(grafo);
  mezclar(libres);
  var monedas = [];
  for(var i=0; i<libres.length; i++){
    var p = libres[i];
    if(p === jugador) continue;              // restriccion 1
    var ok = true;
    for(var j=0; j<monedas.length; j++)
      if(manhattan(p, monedas[j]) < separacion) ok=false; // restriccion 2
    if(ok) monedas.push(p);
    if(monedas.length === cantidad) break;
  }
  return monedas;
}

Conecta con el código

Si subes separacion demasiado, puede que no quepan todas las monedas: el problema se vuelve insatisfacible, un concepto clave de los CSP. Lo verás al mover ese control en el laboratorio.

8 Minimax: un jugador que piensa (Semana 11)

Teoría de juegos y entornos multiagente

El juego tiene un modo automático: un jugador controlado por IA que decide con la idea de Minimax. Entre sus movimientos posibles elige el que lo deja más lejos del fantasma más cercano (maximiza su seguridad), anticipando que el fantasma se acercará (minimiza esa distancia).

// Jugador automatico estilo Minimax (1 nivel)
function jugadorIA(){
  var opciones = grafo[jugador];
  var mejor = jugador, mejorValor = -9999;
  for(var i=0; i<opciones.length; i++){
    var mov = opciones[i];
    // seguridad = distancia al fantasma mas cercano (MAX la quiere grande)
    var seguridad = Math.min(manhattan(mov,fantasma1), manhattan(mov,fantasma2));
    // acercarse a la moneda mas cercana suma
    var cercaMoneda = monedas.length ? -distMinMoneda(mov) : 0;
    var valor = seguridad*2 + cercaMoneda;
    if(valor > mejorValor){ mejorValor = valor; mejor = mov; }
  }
  return mejor;
}

Conecta con el código

Activa el botón "Modo IA" en el laboratorio y observa cómo el jugador se mueve solo: huye y busca monedas a la vez. Tu reto será hacerlo mirar dos pasos adelante, no solo uno.

9 Laboratorio: personaliza el juego (Semana 2)

Cambia los valores y juega de nuevo

Aquí conectas la teoría con la práctica moviendo los controles. Cada cambio modifica el comportamiento real del juego de arriba. Experimenta, juega, y anota qué observas: eso es la base de tu entregable.

Retos del laboratorio (elige al menos cuatro para tu entregable)

  1. Interfaz: en el código, cambia los colores del jugador o de los fantasmas.
  2. CSP: sube la separación de monedas hasta que el juego no pueda colocarlas todas. ¿Por qué ocurre? (insatisfacibilidad).
  3. Algoritmos: pon la heurística en "Cero" y observa si el fantasma rojo se vuelve menos certero (actúa como BFS).
  4. IA de fantasmas: haz la distracción dinámica en el código (que baje cuando el fantasma está lejos). Pista: edita pasoFantasma.
  5. Minimax: mejora jugadorIA para que mire dos pasos adelante.
  6. Nivel propio: edita la variable MAPA en el código para crear tu propio laberinto.

Cómo editar el código

Como esta guía corre en el navegador, para editar el código a fondo (colores, IA dinámica, tu mapa) abre el archivo HTML con "Ver código fuente" o en un editor, busca la sección <script> y modifica las variables y funciones que leíste. Guarda y vuelve a abrir el archivo para ver tus cambios. Documenta cada cambio con una captura.
